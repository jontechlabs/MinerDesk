# MinerDesk 0.8.1 — Fleet, now in the stable release

Manage your Windows and Linux rigs from any paired MinerDesk instance. Fleet is optional and off by default; existing local profiles, schedules and Fleet pairings are preserved.

## Easier pairing

Joining a fleet now asks only for the coordinator's HTTPS address and its temporary invitation key. MinerDesk uses the local machine's name automatically. Create a fresh single-use invitation on the coordinator for each new rig; **Find on network** can suggest the address on the LAN.

## The rig dashboard inside Fleet

Opening a rig shows its mining dashboard: active miners, algorithm-specific hashrates, engine-reported power, maximum temperature, accepted/rejected shares and per-profile uptime, with the miner details and controls together. The opened view refreshes as new snapshots arrive. Unavailable readings remain unavailable, and disconnected rigs are marked stale rather than shown as confirmed stopped.

These are the same runtime measurements used by the local dashboard, not a separate profitability estimate or a measurement at the wall. Fleet retains the existing profile editor, GPU settings, local-time schedules and filtered logs. Root/administrator approvals remain on each rig.

## Update directly from MinerDesk

This is a **stable release** with signed, verified application-update assets. On supported desktop installations, open **Settings → Application updates → Check now**, then confirm **Update…**. Installed Windows x64, installed Debian packages with graphical administrator approval, and writable Linux AppImages support in-app installation. Portable, browser/headless and unsupported installations receive the GitHub download link.

The updater preserves configuration and downloaded mining engines. Mining is stopped only after download and signature verification; manually started mining may need restarting afterward. Application-update signatures are separate from Windows Authenticode and do not guarantee the absence of SmartScreen warnings.

## First Fleet setup

1. Open **Fleet** on one PC and create a coordinator using a reachable LAN or VPN HTTPS address.
2. Generate an invitation on that PC.
3. On each other PC, find the coordinator or paste its address, then paste a fresh invitation key.

Fleet normally uses TCP **17889** and optional LAN discovery uses UDP **17990**. Across networks, use a trusted VPN or deliberately configure coordinator HTTPS reachability and the firewall/router. A network interruption does not stop already running local mining or schedules while the local backend remains alive. All paired instances are trusted controllers; this release does not add granular user roles or automatic coordinator failover.

Windows setup, Debian, AppImage, portable archives, source, update signatures, `latest.json`, build provenance and SHA-256 checksums accompany this release. The portable archives include the [Fleet guide](../FLEET.md). Native platform checks and isolated integration fixtures are recorded in the build provenance; no live GPU benchmark is claimed.

## Français

Fleet rejoint le canal stable. **Rejoindre une flotte** demande seulement l'adresse HTTPS et la clé d'invitation ; le nom de la machine est automatique. Ouvrir un rig affiche désormais ses mesures et sa liste de mineurs ensemble, avec actualisation : hashrate, puissance, température, ventilation, shares et durée de fonctionnement.

Sur une installation compatible, allez dans **Paramètres → Mises à jour de l'application → Vérifier maintenant**, puis confirmez la mise à jour. Les profils, horaires, mineurs téléchargés et associations Fleet sont conservés. Les autorisations administrateur restent locales.
