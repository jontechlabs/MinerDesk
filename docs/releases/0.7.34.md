## Clear Windows GPU discovery diagnostics

MinerDesk 0.7.34 displays the exact operating-system error directly beside failed GPU detection. Windows access refusals (error 5) now point to file permissions and Windows Security protection history, with no Linux-only instructions.

- Preserve native Windows launch-error codes independently of the system's language.
- Choose launch guidance using the backend operating system, including when a browser on one OS connects to another.
- Keep engine GPU IDs, saved selections and tuning unchanged. System adapter indices remain reference-only when the engine's listing cannot be verified.
- Add a [Windows troubleshooting guide](https://github.com/jontechlabs/MinerDesk/blob/main/docs/WINDOWS-MINER-DETECTION.md) explaining quarantine, the scope of miner-directory exclusions and other Windows protection layers.

This update improves diagnostics; it does not disable security features, restore quarantined files or add exclusions automatically. Windows denying access to a third-party engine must be resolved on that PC. A folder exclusion is not a guarantee against every protection layer. Signing MinerDesk does not sign its downloaded mining engines.

Windows and Linux binaries are rebuilt from the same revision. Windows Authenticode signing remains pending provider configuration; application-update signatures are verified as usual.

Validation covers frontend diagnostics in English and French, native Windows console capture and invalid-executable errors, GPU selector safety, and existing Linux terminal/root supervision regression tests. No live mining profiles or security policies were changed by the test suite.
