## Fix Windows startup stuck on the loading screen

**MinerDesk 0.7.36 fixes the startup regression introduced in 0.7.35.** With existing mining profiles, the status poll could return before configuration/native backend discovery finished. The dashboard then read schedules from a null configuration, crashed, and left “Checking MinerDesk backend…” on screen even though the backend was running.

- Handle early miner status safely, including older status payloads without a schedule flag. Once loaded, the current configuration determines schedule membership.
- Keep mining controls disabled until connected and dismiss the splash after successful initialization.
- Add whole-application tests that deliberately deliver status before native/config responses, including stale flags and browser dashboards. The regression tests reproduce the 0.7.35 crash and pass with this fix.
- Preserve the schedule-aware Start/Restart/Start all behavior, explicit Force mining/Resume schedule controls, and both Windows installer registry views.

**If 0.7.35 is stuck loading:** close MinerDesk, install `MinerDesk_0.7.36_x64-setup.exe`, then reopen it from the Start menu. Profiles, schedules and wallets do not need resetting. The previous release is withdrawn from stable updates; its assets remain available for reference.

Windows and Linux binaries are rebuilt from the same revision, with independently verified application-update signatures and checksums. Windows Authenticode signing remains pending provider configuration. No antivirus settings or live mining profiles are changed by the tests.
