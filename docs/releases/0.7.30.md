# MinerDesk 0.7.30 — Clear GPU tuning and actionable miner errors

An old global power limit could return when a per-GPU field was cleared. The table now shows the effective saved values, and explicit GPU edits no longer inherit hidden defaults. **Clear all GPU tuning** clears both global and per-GPU clock, power and fan settings without changing wallets, pools or GPU selection.

- Validate SRBMiner power-limit arguments before launch, including Advanced arguments. A value such as `2100` is rejected with the option name, units and accepted parser range.
- Explain GPU core frequency in MHz versus GPU power in watts. The miner's 0–1000 power parser range is separate from GPU clock values and hardware-specific power limits.
- Report incomplete SRBMiner multi-GPU tuning lists instead of silently dropping their settings.
- Show an available recent miner error next to a nonzero exit code, in English or French, including output received just after process exit.
- Quote rig names and executable paths containing spaces in the console command. Engines continue receiving the same separate arguments directly.

If an older profile emits `--gpu-plimit0 2100`, use **Clear all GPU tuning**, save and retry. You can then add a supported GPU clock or power setting deliberately. Blank tuning omits the corresponding MinerDesk option; it does not reset previous driver-level settings or remove options written separately in Advanced arguments. See [GPU tuning guidance](https://github.com/jontechlabs/MinerDesk/blob/main/docs/GPU-TUNING.md).

Profiles, schedules and downloaded engines are preserved. Windows downloads remain unsigned with Authenticode; updater signatures are provided separately.
