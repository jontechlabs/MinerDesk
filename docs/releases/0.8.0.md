# MinerDesk 0.8.0 — Fleet for your Windows and Linux rigs

Fleet brings several MinerDesk rigs into one dashboard. Choose one coordinator, pair trusted Windows/Linux instances with a temporary invitation, then monitor the group and issue commands from any paired instance. Fleet is optional and **off by default**; existing standalone profiles and schedules remain available.

## Get started in three steps

1. Open **Fleet** on the coordinator PC. Choose a name and review the suggested LAN HTTPS address, normally `https://YOUR-LAN-IP:17889`.
2. Generate a temporary **single-use invitation**. Transfer the complete address/key privately to the next rig.
3. Join from that rig using the address and invitation. LAN discovery can suggest a coordinator address, but does not replace the trusted invitation. Repeat with a new invitation for each rig.

Fleet agents make outgoing HTTPS requests to a pinned coordinator identity. The coordinator normally listens on TCP 17889; optional discovery uses UDP 17990. For rigs on different networks, use a trusted VPN or explicitly provide coordinator HTTPS reachability through the router and firewall. No automatic UPnP port mapping is performed. Do not expose the separate plain HTTP API on 17888 to the public Internet.

## What you can manage

- Timestamped status and filtered recent logs, with offline/stale status distinguished from a confirmed stop.
- Start, Stop, Restart and Resume using the existing schedule policy. **Force mining** is the explicit unlimited override.
- Revision-checked edits to stopped profiles: pool, public receiving address, worker, supported GPU settings and other permitted fields. Local executable paths, engine selection, passwords, Advanced arguments and root references are preserved.
- Mining windows and assignments in each rig's local timezone. Existing local sleep, wake and confirmation controls remain local.
- Expiring commands, per-rig receipts and a persistent execution journal; ambiguous results are not silently retried.

Each rig keeps running its local mining and scheduler during a coordinator/network outage while its backend remains alive. With Fleet enabled, closing the Windows window detaches its interface and retains the backend; closing the Linux window hides the application with tray access. **Quit** is the explicit stop/exit action. Fleet does not install a boot service or guarantee continued operation after logout, a process crash or computer shutdown.

## Trust and privacy

Every paired instance is a trusted controller of the group. This first version does not provide granular viewer/operator/admin roles, automatic coordinator failover or a remote shell. Pair only computers and accounts you trust with that access.

Public receiving addresses and permitted profile settings are visible in the controller configuration view. Periodic telemetry excludes wallet identifiers and private configuration; command lines and credential/path-bearing output are filtered from remote logs. Fleet never needs wallet private keys, seed phrases or root/administrator passwords. Linux root enrollment stays on the rig, and a changed command can require renewed local approval. No Fleet start opens an interactive password dialog.

Protect and privately back up `fleet-private/state.json` beside the MinerDesk configuration. It contains coordinator identity/private TLS material, membership credentials and command history. Current rig telemetry stays in memory; heartbeats do not rewrite credentials. Losing that private state can require pairing again. Read the [Fleet guide](../FLEET.md), [security model](../../SECURITY.md) and [privacy policy](../PRIVACY.md).

## Downloads and validation

Choose the asset for your system in the published release: Windows x64 setup/portable ZIP; Linux x64 `.deb`, AppImage or portable archive. Names use version **0.8.0**, such as `MinerDesk_0.8.0_x64-setup.exe` and `MinerDesk_0.8.0_amd64.deb`. Check `SHA256SUMS.txt` and the release's package/signing information. Application-update signatures and Windows Authenticode are separate mechanisms.

Local validation: **127 Rust library tests on Linux and 97 Node tests, including 17 Fleet UI tests, passed**. Three isolated headless processes also exercised pairing, remote edits, conflicting revisions, coordinator outage/restart and access revocation without launching a mining engine. Platform packaging and Windows execution are checked separately by the [build workflow](https://github.com/jontechlabs/MinerDesk/actions/workflows/ci.yml); consult the release's build provenance for the exact revision and run. No live GPU benchmark is claimed.

## Français

La version 0.8.0 ajoute **Fleet**, désactivé par défaut, pour surveiller et piloter des rigs Windows/Linux depuis les instances associées. Créez un coordinateur, générez une invitation temporaire à usage unique puis associez chaque rig avec l'adresse et la clé reçues dans un échange privé. La découverte LAN fournit seulement un indice d'adresse.

Les horaires et le minage restent locaux. Une panne du coordinateur n'arrête pas un backend encore ouvert. Avec Fleet actif, fermer la fenêtre Windows détache l'interface ; sous Linux, cela masque l'application avec accès par la zone de notification. **Quitter** arrête explicitement l'application et son backend. Aucun service automatique au démarrage du système n'est installé.

Toutes les instances associées sont des contrôleurs de confiance, sans rôles détaillés dans cette première version. Les adresses de réception publiques sont visibles dans la configuration opérateur. Les clés privées de wallets et mots de passe root ne sont jamais nécessaires ; les autorisations root restent locales. Sur plusieurs réseaux, prévoir un VPN ou configurer volontairement l'accès HTTPS au coordinateur, le routeur et le pare-feu. Aucun port n'est ouvert automatiquement par UPnP.

Consultez le [guide Fleet bilingue](../FLEET.md). La validation locale comprend 127 tests Rust Linux et 97 tests Node, dont 17 tests d'interface Fleet, ainsi que des essais entre trois processus indépendants sans moteur de minage réel. Les résultats Windows et la provenance des paquets sont fournis par le workflow de compilation et les fichiers de la publication.
