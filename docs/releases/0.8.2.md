# MinerDesk 0.8.2 — Update your rigs from Fleet

Manage future signed MinerDesk upgrades from any trusted paired instance. Select rigs, check their offered version, review the mining interruption and confirm a rolling update. Fleet updates one rig at a time and keeps the coordinator for last.

## One-time setup

Install **0.8.2** on each rig through its existing local updater, then enable **Fleet → Connection & fleet → Allow remote updates on this machine**. Debian/Ubuntu/Lubuntu also require **Authorize once on Linux**, using the operating system's local administrator dialog. No administrator password is stored or transmitted. Writable AppImages need no root grant; Windows uses its installed elevated backend.

Older agents cannot receive this feature remotely until that initial upgrade. After activation, future supported updates can be requested centrally. Existing Fleet pairings, profiles, downloaded engines and schedules are preserved.

## Know what is happening

- Per-rig version, update eligibility and progress, with explicit reasons for excluded rigs.
- Downloads and signature checks before mining stops; the detached worker independently verifies the publisher and signed version again.
- Durable rollout intent and command identities, avoiding automatic reinstallation after a lost acknowledgement.
- Confirmation from a fresh report by the expected or a newer binary and matching worker completion before the next rig starts.
- Stop remaining targets on failure; cancel pending targets while an installation already committed finishes.
- Local opt-out and Debian authorization revocation, kept outside remotely editable profile configuration.

Supported targets are registered Windows x64 NSIS installations with the elevated backend, authorized Debian x64 installations and writable Linux x64 AppImages. Portable, development, old, read-only or unsupported rigs are excluded. A manually started mining session may need restarting after an application update; local schedules retain their usual rules.

This stable release includes version-bound update signatures and the usual Windows setup, Debian/AppImage, portable archives, source, build provenance and checksums. Application-update signatures remain separate from Windows Authenticode. No live GPU benchmark or unattended installation on a user's rig was performed during fixture verification.

Read the [Fleet update guide](https://github.com/jontechlabs/MinerDesk/blob/v0.8.2/docs/FLEET-UPDATES.md) for activation, rollout behavior and recovery limits.

## Français

Fleet peut désormais déclencher les futures mises à jour signées de vos rigs depuis un seul PC. Après une installation initiale de 0.8.2 et une activation locale unique sur chaque machine, vérifiez les versions, sélectionnez les rigs et confirmez le déploiement. Sous Debian/Lubuntu, autorisez une fois l'assistant système ; aucun mot de passe administrateur n'est mémorisé.

Les mises à jour avancent une par une, coordinateur en dernier. Le téléchargement et la vérification précèdent l'arrêt du minage. La réussite attend un rapport récent du nouveau binaire avec la version attendue ou plus récente, ainsi que la confirmation de fin de l'assistant pour la même opération ; un échec arrête le restant. Les associations Fleet et configurations sont conservées.
