# MinerDesk 0.7.31 — Memory clocks and complete GPU tuning

Configure GPU memory clocks directly in MinerDesk. Each GPU now has a readable card with the controls supported by the selected engine:

- Fixed core and memory clocks, in MHz.
- Signed core and memory clock offsets, in MHz.
- Power limit, in watts, and fan speed, in percent.

SRBMiner, lolMiner, BzMiner and Rigel receive their own documented options. NPMiner gains its CUDA memory-clock lock alongside core clock and power. lpminer retains its shared core-clock lock; unsupported controls are hidden rather than accepting ineffective settings.

Existing profiles keep their original settings. Newly added fields are blank, and no overclock preset is applied. Explicitly clearing any GPU field omits that override without reviving a global default. **Clear all GPU tuning** also clears the new fields. Save before starting; stopping, editing and starting rebuilds the arguments.

Fixed clocks and offsets are different settings. Driver permissions, supported memory states, GPU model and algorithm determine what the mining engine can apply. A reported memory frequency is not necessarily the value accepted by a clock-lock command. lolMiner documents memory locks mainly for KASPA/ALPH. See the [GPU tuning guide](https://github.com/jontechlabs/MinerDesk/blob/main/docs/GPU-TUNING.md) for the engine mappings.

Incomplete SRBMiner/NPMiner tuning lists, partial BzMiner memory/offset lists and fan percentages above 100 now produce useful errors instead of silently discarding settings. BzMiner's new controls never replace a blank with zero, which could unlock clocks on some versions. Mining lifecycle, wallets, pools and schedules are preserved. Windows downloads remain unsigned with Authenticode; updater signatures are provided separately.
