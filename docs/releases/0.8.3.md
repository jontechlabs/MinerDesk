# MinerDesk 0.8.3 — Windows update recovery with Fleet

This maintenance release fixes a Windows in-app update failure that could display **“Backend is still running; update cancelled”** even after the other MinerDesk Desktop processes had exited.

## What changes

- Fleet now removes connections belonging to verifiably exited Desktop processes without stopping its autonomous backend or mining sessions merely because the UI closed.
- An explicit backend shutdown rechecks other Desktop connections. A live process, or one whose state cannot be verified, remains protected; independent standalone headless instances are not taken over by the Desktop updater.
- The updater validates the backend's shutdown acknowledgement and reports refusal reasons instead of reducing them to a generic timeout. Installation waits for shutdown within a bounded deadline.
- Package download and signature verification still happen before mining stops. There is no forced process termination, unsigned fallback or change to Windows security settings.

Profiles, schedules, downloaded engines, Fleet pairings and local Fleet-update policy are preserved. Linux retains its existing update path; Windows and Linux packages are built from the same source revision with version-bound application-update signatures.

## If the old Windows version cannot install this fix

First save your configuration and stop mining. Keep only one MinerDesk Desktop instance open on that PC, including windows hidden in the notification area, then try **Restart backend** followed by **Update…** again. Other PCs connected through Fleet do not need their interfaces closed for this local check.

If the old version still cannot stop its backend, download **MinerDesk_0.8.3_x64-setup.exe** from this release and run the setup once over the existing installation. Use the installer's normal Windows administrator approval and maintenance prompts. There is no need to delete your configuration, miners or Fleet data. Launch MinerDesk from the Start menu afterward; future supported updates can use the normal in-app flow.

If a new error says that another Desktop process or a standalone backend is active, resolve that specific condition before retrying. Manual mining sessions may need restarting after installation; saved schedules retain their normal behavior.

Application-update signatures are separate from Windows Authenticode and do not remove SmartScreen warnings. No live GPU benchmark or unattended installation on a user's rig is claimed by this release.

See the [update guide](https://github.com/jontechlabs/MinerDesk/blob/v0.8.3/docs/UPDATES.md) for supported installations and recovery.

## Français

Cette version corrige un blocage de la mise à jour Windows lorsque Fleet conservait la connexion d'une ancienne interface MinerDesk déjà fermée. Le backend pouvait alors refuser son arrêt et afficher **« Backend is still running; update cancelled »**.

Les connexions des processus dont l'arrêt est vérifié sont nettoyées, tout en conservant l'autonomie de Fleet. Une autre interface réellement active, un état de processus incertain ou un backend headless indépendant restent protégés. La demande d'arrêt reçoit désormais un accusé de réception vérifié et les refus sont expliqués plus clairement.

Si votre ancienne version ne peut pas installer ce correctif, enregistrez, arrêtez le minage, fermez les interfaces supplémentaires sur ce PC puis essayez **Restart backend** et **Update…**. Si le blocage persiste, installez une fois le setup **0.8.3** de cette page par-dessus l'installation existante. Aucun effacement des profils, horaires, moteurs téléchargés ou associations Fleet n'est nécessaire.
